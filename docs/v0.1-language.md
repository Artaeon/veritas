# Veritas V0.1 Language and Execution Semantics

## Minimal grammar

The grammar is line-oriented. Blank lines and text after `#` are ignored.
Identifiers match `[A-Za-z_][A-Za-z0-9_]*`. Keywords are lowercase and
case-sensitive. Each declaration occupies one line except a rule block.

```ebnf
bundle      = header, declaration* ;
header      = "bundle", identifier, "@", version ;
declaration = type-decl | attribute-decl | predicate-decl
            | entity-decl | fact-decl | rule-decl ;

type-decl      = "type", type-name ;
attribute-decl = "attribute", type-name, ".", property, ":", primitive ;
predicate-decl = "predicate", type-name, ".", property ;
entity-decl    = "entity", entity-name, ":", type-name ;
fact-decl      = "fact", entity-name, ".", property, "=", literal ;

rule-decl  = "rule", identifier, "(", variable, ":", type-name, ")", ":",
             condition-line, condition-line*, effect-line, "end" ;
condition-line = "when", expression | "and", expression ;
effect-line    = "derive", reference, "=", literal ;
expression     = reference, operator, literal ;
reference      = variable, ".", property ;
operator       = "=" | "!=" | "<" | "<=" | ">" | ">=" ;
primitive      = "Boolean" | "Integer" | "Decimal" | "String"
               | "Symbol" | "Date" | "Duration" ;
literal        = boolean | integer | decimal | string | symbol | date | duration ;
```

Example:

```veritas
bundle people@0.1.0
type Person
attribute Person.age: Integer
predicate Person.adult
entity john: Person
fact john.age = 21

rule adult_age($person: Person):
  when $person.age >= 18
  derive $person.adult = true
end
```

## Typed IR

IR is separate from source syntax and carries `irVersion: 1`:

```text
KnowledgeIR {
  irVersion, bundle { name, version }, types[], properties[], entities[],
  facts[], rules[], canonicalHash
}

PropertyIR { ownerType, name, valueType, kind: attribute | predicate }
EntityIR   { name, type }
FactIR     { id, entity, property, typedValue, source }
RuleIR     { id, name, variable { name, type }, conditions[], effect, source }
ConditionIR { property, operator, typedValue }
EffectIR    { property, typedValue }
```

Arrays are sorted by stable semantic keys before hashing and runtime use. Source
locations and the hash itself are excluded from canonical bundle serialization.

## Exact execution algorithm

1. Seed a multimap from cell keys to supported typed values using initial facts.
2. Sort entities by name and rules by ID.
3. For each `(rule, matching entity)` pair, evaluate all conditions against the
   current immutable fact snapshot.
4. If every condition is true, create the effect support and a derived proof.
5. Merge new support in stable key order. Duplicate support changes nothing.
6. Repeat from step 3 until a full round adds no support.
7. Evaluate the query from the final support set.

Comparison with missing data has no positive support. When several values are
supported, matching and non-matching evidence are retained independently. A
rule condition is satisfied by at least one matching support even if contrary
support exists; its proof cites a canonical matching branch. The normative
contract is defined in `docs/semantics-v0.1.md`.

## V0.1 exclusions

There is no closed-world negation. `!= false` does not mean “not known false.”
Rule effects must be literals, so the derivable universe is finite. There are no
entity constructors, external calls, dynamic imports, or current-time access.
